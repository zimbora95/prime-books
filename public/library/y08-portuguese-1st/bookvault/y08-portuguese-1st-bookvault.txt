NOTES
--------------------------------------------------------------------------
  * In a Prime Books PDF, page 1 is the front cover and the last page
    is the back cover. Both are reprinted inside the cover file, so
    they are removed from the text file: y08-portuguese-1st.pdf has 177 pages,
    this text file has 175.
  * Rules followed here are from BookVault's 'Your Guide to Supplying
    Print-Ready PDF Files', kept in docs/bookvault/ together with the
    two templates they published for this book:
      bleed 3 mm on every edge (p.5); text file media box is
      trim + bleed = 216 x 303 mm (p.5,p.18)
      page count supplied: 175 (175 of book); their production barcode
      page is added at the rear whatever count is supplied (guide p.5;
      over Royal/US Royal size their help centre asks for 4n-1)
      first page prints on the first right-hand page (p.5), so page 1 is a
      recto. Prime Books pages are not mirrored, so no layout moves; the
      binding-edge check below measures the real clearance instead
      covers inset: content kept 5 mm clear of the cover trim (p.19)
  * Bleed is extended from each page's own edge artwork, so the running-
    header band and any full-bleed art carry to the trim line with no gap.
  * Spine: guide p.18 takes it from the sizing calculator and rounds UP to
    a whole mm. This build uses 0.056 mm per page (their 80gsm bond example:
    100 pages = 5.6 mm). Run the calculator for the paper you choose, then
    rebuild with --spine-mm <mm> and the OPEN check below clears.
  * Colour: guide p.6 prefers CMYK with a FOGRA profile, and accepts RGB.
    This file is converted to CMYK through Ghostscript's default CMYK
    profile, not a FOGRA one - ask BookVault for their output profile and
    rebuild with --profile <icc> if the press is calibrated.
  * FONT EMBEDDING (BookVault's check, the one this book failed):
    the interior carried fonts with no program behind them -- base-14
    Helvetica, which pymupdf edits leave behind, and Type 3 fonts,
    which are glyph programs rather than font files. Neither can be
    embedded, so the pack outlines those glyphs: they were vector art
    already, and the page renders pixel for pixel the same. The
    11346 text spans are re-laid invisibly in ONE
    embedded font, so the file still searches and still copy-pastes.
    Fonts replaced: (all Type 3)
